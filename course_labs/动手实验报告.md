## Hugging Face Datasets 与 Tokenizers

对应 L2 Part 1 第 87、104 页。2026-11-24 在 Hugging Face 公开页面完成第 5、6 章的章末测验，两章各十题。页面判定选择正确，启用章节完成按钮，点击后分别进入第 6、7 章。该浏览器未登录，账号进度未核实。 [第 5 章测验](https://huggingface.co/learn/llm-course/en/chapter5/8) · [第 6 章测验](https://huggingface.co/learn/llm-course/en/chapter6/10)

- **第 5 章。** 从本地构造 4,200 条 Dataset，过滤空行，map 补词数，用固定种子切成 3,570/630，再保存和读回。Arrow 磁盘映射可以按需读页，按迭代方式读取时可用 streaming。原练习用字符 TF-IDF 做精确余弦检索。补跑使用 `load_dataset` 的 streaming 模式读取前 512 条新闻片段，用本机 `bert-base-chinese` 的最后一层生成 768 维向量，平均时排除特殊 token 和填充，再做 L2 归一化。FAISS 按内积检索，索引保存并加载后，三个查询各自的前 3 条结果和分数均与 NumPy 穷举一致。
- **第 6 章。** 先区分规范化、预分词、模型及后处理。训练 BPE、WordPiece、Unigram 三者，并用 BERT fast tokenizer 的原管线训练一个新词表。BPE 贪心合并频繁片段，WordPiece 基于分词单元得分，Unigram 从大词表迭代裁剪。用 input ids 检查未知项，不能仅按 token 显示文字计数。
- **QA offset 检查。** 只从 sequence_id=1 的材料定位答案。示例中 WTO 的 offset 为 14–17，虽由旧词表表示成 [UNK]，仍可回到原材料跨度。依靠显示 token 无法保证内容可逆；断句也用同一种 offset 处理机制。

代码 [data_and_tokenizers.py](data_and_tokenizers.py)，结果 [data_and_tokenizers.json](results/data_and_tokenizers.json)。

FAISS 示例中，「农业科技与农民收入」排名第一的是农技协会帮助农民科技致富的报道，余弦相似度 0.8340。「学校开展素质教育」排名第一的是中学教育改革的报道，余弦相似度 0.8607。新闻片段按原文顺序取样，部分命中来自同一篇。三个查询用于核对索引流程和结果，检索质量还需要更多查询、相关性标注和按文章去重。 [官方 FAISS 练习](https://huggingface.co/learn/llm-course/en/chapter5/6) · [补跑代码](faiss_search.py) · [补跑结果](results/faiss_search.json)

## 古汉语罕见字与旧词表迁移

对应 L2 Part 2 第 231–264 页。选异体字、常用字成对评估。基线训练只用相同的 4 月现代语料、6000 词表预算、NFC。稀有字小测试对比原词表和附加 4 个明确字项。按输入缺失、可逆性、序列长度分别比较。

四条含异体字样本的 BBPE 缩短 **45→36 个 token**，均能原样解码。WordPiece 的未知 token 从 **13→9**，附加字项只修复覆盖到的字符，其他罕见字仍会丢失。Unigram 的四条测试共出现 8 个未知 ID。不同预分词和解码接口会影响这些数字，单测只支持这批输入上的比较。添加条目属于接口演练，尚未训练替换后的预训练模型参数。

实际迁移时先固定同一底座和切分。A 原 BBPE＋token 掩码，B 只改原文字符跨度掩码，C 保持 B 掩码、继续旧 BPE 学习并初始化新增行，D 改用上下文取均值，E 加受验证的异体和构件先验。覆盖恢复单独用 WordPiece 保留原嵌入行、复制映射及新增行初始化比较。任何映射都保留新旧字符独立 ID。跨字节 token 的跨度需要闭包并统计多遮蔽位置。训练报告同时给固定原文量与固定 FLOPs 的结果，按书目和近重复版本留出，比较异体保持、罕见字下游指标、标注对齐、现代新闻回归和实际推理成本。若序列缩短但罕见字或回归恶化，回到未扩展基线。

## 新闻文本分段

对应 L2 Part 1 第 48 页。每篇新闻以 45 词为一段，从同文取相邻片段作负样本，把不同文章片段相接作正样本。先按文章切分，1,986 篇训练、497 篇留出，再组配样本。用字符 TF-IDF 相似度训练单特征逻辑回归。

恒预测边界的宏 F1 为 0.3333，按训练相似度中位数划分为 0.9497，逻辑回归为 0.9516。结果说明在合成的跨新闻切换代理任务上相似度区分有效。 [脚本](segment_text.py) · [指标和错例](results/segmentation.json)

调研时分别看句子边界和主题分段。需要跨中英文识别无标点句界时，可将多语 SaT 与语言专用规则比较。做段落主题分界时，TextTiling 提供可解释词汇凝聚基线；英文长篇 RAG 可比较原始标题、固定长度和 LumberChunker 的动态话题块。当前没有一套公开成绩能据此宣布中文段落和英文长叙事使用同一个最优模型。建议在同一文档切分和检索器下比较边界 F1、证据 Recall@K、回答准确率和资源。 [SaT 原文](https://aclanthology.org/2024.emnlp-main.665/) · [TextTiling 原文](https://aclanthology.org/J97-1003/) · [LumberChunker 原文](https://aclanthology.org/2024.findings-emnlp.377/)

### 中英文自然段落与证据检索复跑

中文使用 DRCD，英文使用 SQuAD 1.1。保留数据集给出的文章分组和段落顺序，按文章固定划分，开发集标定阈值后一次评估留出集。中文留出 65 篇、270 段、954 问，英文留出 16 篇、611 段、2,977 问。候选位置为句间，参考边界为公开数据里的原有段尾。词汇分段比较边界两侧各最多两句的 TF-IDF 余弦距离。固定长度按整句打包，字符软上限取开发集段长中位数，中文 421 字符、英文 699 字符。

| 留出集 | 固定长度边界 F1 | 词汇分段边界 F1 | 固定长度 WindowDiff | 词汇分段 WindowDiff |
|---|---:|---:|---:|---:|
| 中文 DRCD | 0.102 | 0.246 | 0.453 | 0.522 |
| 英文 SQuAD | 0.221 | 0.332 | 0.509 | 0.492 |

检索三组使用同一个 TF-IDF 余弦检索器，同一份文档、问题和答案起止位置。比较固定长度、词汇分段后加同样的长度限制，以及直接使用数据集段落后加同样的长度限制。只在检索结果含同一源文档的完整金标答案跨度时计为命中。等字符预算从前五块按排序依次取正文，最后一块按剩余预算截断，中文预算 842 字符、英文 1,398 字符。

| 语种 | 分块 | Recall@3 | 前三块平均字符 | 等字符预算召回 |
|---|---|---:|---:|---:|
| 中文 | 固定长度 | 96.75% | 1,101 | 95.91% |
| 中文 | 词汇分段 | 96.12% | 822 | 96.23% |
| 中文 | 原有段落 | 96.33% | 927 | 95.39% |
| 英文 | 固定长度 | 83.27% | 1,808 | 81.09% |
| 英文 | 词汇分段 | 81.56% | 1,444 | 81.36% |
| 英文 | 原有段落 | 83.61% | 1,492 | 83.20% |

词汇分段提高两种语言的逐边界 F1，中文的 WindowDiff 上升，说明错切的位置和数量仍有问题。在等字符预算下，英文原有段落召回最高，中文词汇分段略高于固定长度。小差值未做显著性检验。数据集只给出选编段落，段落边界作为参照，实验测的是证据检索阶段，生成回答质量仍需单独评估。 [DRCD 官方发布](https://github.com/DRCKnowledgeTeam/DRCD) · [SQuAD 官方发布](https://rajpurkar.github.io/SQuAD-explorer/) · [数据校验](../data/public_benchmarks/README.md) · [实验代码](segmentation_benchmark.py) · [完整指标及错例索引](results/segmentation_benchmark.json)

## 逐函数理解 nanoGPT

对应 L2 Part 2 第 94–95 页。对照 [nanoGPT 3adf61e 的 model.py](https://github.com/karpathy/nanoGPT/blob/3adf61e/model.py) 与 [train.py](https://github.com/karpathy/nanoGPT/blob/3adf61e/train.py)。以两层字符级 decoder 重建核心程序，使用同一语料完成独立小实验。

| 源码环节 | 张量与计算 |
|---|---|
| train.py · get_batch | 读取训练与验证的 token 流，x 与 y 相错一位，均为 B×s |
| model.py · GPT.forward | 读取字符与位置嵌入，合成 B×s×d，经堆叠 block、最后归一化和绑定权重的输出头得到 B×s×V |
| CausalSelfAttention.forward | c_attn 把 d 投影成 3d，拆 Q/K/V，重排到 B×h×s×d_h，使用 causal SDPA，拼头并做 c_proj |
| Block / MLP.forward | Pre-LN、残差和 d→4d→d 的 FFN。注意力图若被显式存储，规模 B×h×s×s |
| GPT.configure_optimizers | 依参数阶数分开 weight decay，支持的 CUDA 环境可以使用 fused AdamW |
| train.py 训练与评测 | 前向交叉熵、梯度累积、反传和优化。estimate_loss 在验证切分抽样；更大运行可用 DDP 和保存点 |

B=8、s=64、d=64、h=4、L=2，约 266k 参数。每层 QKV、输出投影、FFN 与全方阵注意力分别为 12.58、4.19、33.55、8.39 MFLOPs。公式不含词表头、归一化和 softmax。固定前 31 个位置、替换未来位置，前缀 logits 最大差为 0。5 月训练片段、6 月留出片段，120 次更新后留出字符损失从 7.857 降到 4.527。初稿直接使用嵌入默认初始化并与输出头绑权，初始 loss 被异常尺度推高；改为 0.02 标准差后接近随机分布的 log(V)。这也是核对实现尺度比只看下降幅度更有用的实例。 [重建代码](nanogpt_exercise.py) · [训练结果](results/nanogpt_exercise.json)

## SFT 损失与掩码检查

对应 L3 Part 2 第 79–80 页。两个示例分别有 1、3 个监督 token，使用同一显式 logits 张量时，按 token 平均的损失 **1.8378**，先取样本均值再平均为 **1.2414**。前者让长回答承担更大权重。通过 Qwen chat template 定位两组对话的回答文本，输出逐 token 的监督布尔值。系统、用户、工具返回和补齐留作上下文或填充，不计监督；仅包括完整落在助手文本跨度内的 token。本练习同时监督多轮助手内容，实际训练可另选只监督最后一轮或包括结束 token，必须写清策略。 [核查代码](sft_loss_check.py) · [逐 token 结果](results/sft_loss_check.json)
