# 后训练开源代码分析

版本固定为 Hugging Face TRL **v0.20.0**。函数锚点使用对应 tag，行号随该 tag 固定。这里追踪两类训练器，将原论文目标、库实现及课程本机教学实验分开记录。

## GRPO 数据、采样、奖励和更新

1. **输入与候选组。** 数据项至少有 prompt，奖励函数需要的答案等列由训练器传给评分函数。训练采样器按配置重复同一提示，生成组随后按进程和训练批次切分。见 [_get_train_sampler](https://github.com/huggingface/trl/blob/v0.20.0/trl/trainer/grpo_trainer.py#L875)。
2. **Rollout 与缓存。** _prepare_inputs 在训练步安排新采样或复用已生成批次。_generate_and_score_completions 应用模板、构造提示与结束掩码，生成候选并保留输出和对数概率。见 [输入准备](https://github.com/huggingface/trl/blob/v0.20.0/trl/trainer/grpo_trainer.py#L1143) 与 [生成和评价](https://github.com/huggingface/trl/blob/v0.20.0/trl/trainer/grpo_trainer.py#L1223)。
3. **奖励与优势。** 进一步将各奖励按权重组合，按组中心化，根据配置缩放。全对或全错组的中心化优势为零，单独的 KL 或其他项仍可能提供梯度。Tensor 应按“每种奖励、每个候选、每个完成 token”核对广播和聚合。旧策略用于重要性比率，参考策略用于 KL。二者的角色与更新频率不同。
4. **参数更新。** 对生成位置算当前 logp，当前与旧策略的差取指数得比率，裁剪后乘优势；有 β 时加近似 KL。根据配置对 token 或样本聚合，再由 Trainer/Accelerate 调用优化器。不同 loss_type 变体要单独报告。见 [_compute_loss](https://github.com/huggingface/trl/blob/v0.20.0/trl/trainer/grpo_trainer.py#L1651)。
5. **小型单步核对。** 对一题四候选奖励 [1,0,1,0]，均值为 0.5，第一、第三优势为正。置策略与旧策略相同，则比率为 1；反向传播仍会让好候选更可能。若观测到反方向，先核对标签、completion mask 与 min 的符号。

## DPO 数据、对数比与更新

1. **数据准备。** 使用同一 prompt、chosen、rejected，编码并按配置截断。见 [tokenize_row](https://github.com/huggingface/trl/blob/v0.20.0/trl/trainer/dpo_trainer.py#L603)。
2. **前向与掩码。** 将优劣两批拼接，取 completion 的 token logp，分别合成序列 logp，再拆回 chosen/rejected。见 [concatenated_forward](https://github.com/huggingface/trl/blob/v0.20.0/trl/trainer/dpo_trainer.py#L1292)。
3. **偏好损失。** 对经典 sigmoid 选项，令 Δ 等于策略优劣差减参考优劣差，损失为负 log sigmoid(βΔ)。优劣的顺序、掩码和参考 logp 必须一致。参考对数概率可预计算；变体损失需另标。见 [dpo_loss](https://github.com/huggingface/trl/blob/v0.20.0/trl/trainer/dpo_trainer.py#L899)。
4. **训练与评测。** get_batch_loss_metrics 把分支输出和对数比送入损失并记录统计。Trainer 用该损失反传。评价要留同一个独立任务集并额外跑实际生成，偏好对上的 reward accuracy 只是目标诊断。见 [get_batch_loss_metrics](https://github.com/huggingface/trl/blob/v0.20.0/trl/trainer/dpo_trainer.py#L1490)。

## 研究来源与本机证据

GRPO 原始目标来自 [DeepSeekMath](https://arxiv.org/abs/2402.03300)，DPO 来自 [Rafailov 等](https://arxiv.org/abs/2305.18290)。上面解释的是固定 tag 的通用开源实现。工业报告中的额外验证器、数据、并行和策略版本管理按其披露为准。

本机另外用 [小策略](run_tiny_posttrain.py) 跑了 SFT 与组相对更新，相同输入抽样、相同初始权重。结果见 [实测 JSON](results/tiny_posttrain.json)。两臂均在 21 个留出组合上答对 13 个，初始仅答对 3 个。SFT 为 160 次参数更新，组相对路线为 320 次及 40,960 次验证器调用。这个例子用于说明反馈和算力口径，模型只有三类单 token 输出，无法比较长链推理。
