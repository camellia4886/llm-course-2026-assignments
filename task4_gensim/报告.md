## 独立语料表示学习

用 CMRC 2018 训练集的中文维基百科正文训练表示，读取 2,403 段正文，不读取问题和答案。段落去重后按句末标点切分，用 jieba 0.42.1 和 `HMM=False` 分词，得到 **27,641 句、742,789 个 token、14,601 个入词表词项**。与人民日报 9801 的分词句子做了精确匹配，本次未发现同样的词序列。

训练保持 v2 的 100 维、skip-gram、窗口 5、最小词频 5、4 轮。FastText 使用 2–4 字符 n-gram 和 30 万桶。本次 CPU 计时为 Word2Vec 2.33 秒、FastText 2.96 秒。分类仍使用 9801 新闻中的同一组弱标注、词表内均值向量和固定五折划分。六类分类语料的词表覆盖率为 **81.52%**，每篇至少命中一个词。

| 类别 | 新闻样本 | Word2Vec LR | Word2Vec SVM | FastText LR | FastText SVM |
|---|---:|---:|---:|---:|---:|
| 2 | 1,028 | 0.843 | 0.844 | 0.854 | 0.867 |
| 4 | 1,503 | 0.782 | 0.781 | 0.796 | 0.798 |
| 6 | 1,828 | 0.709 | 0.720 | 0.749 | 0.755 |

FastText 的「足球」首邻词为「足球队」，对词表外的「电子计算机化」能给出向量。Word2Vec 的三个示例类比首选均不正确。相比新闻训练的跨月份版本，本次外部语料的分类分数更低。主题、规模和分词同时变化，单次对照无法分离各因素的影响。分类仍按弱标签评分。

## 3. 实验设置

### 3.1 词向量训练

```python
common = dict(vector_size=200, window=5, min_count=5, sg=1,
              workers=4, epochs=5, seed=42)
w2v = Word2Vec(sentences, **common)          # skip-gram + negative sampling
ft  = FastText(sentences, min_n=2, max_n=4, **common)  # 字符 2~4-gram
```

- 选择 `sg=1`（skip-gram）而非 CBOW：论文结论是 skip-gram 在罕见词与大规模语料上更好；`negative=5` 为默认负采样。
- FastText `min_n=2, max_n=4`：中文"子词"即单字与 2–4 字片段，比英文默认的 3–6 更贴合汉字形态（词由 1~2 个字起步），OOV 也能靠子词拼出向量。
- 耗时（CPU 4 线程）：Word2Vec **16.7s**，FastText **25.9s**（FastText 多了子词表与哈希，符合预期）。

### 3.2 演示实验

- 相似词：`model.wv.most_similar()`；
- OOV：用词表中**不存在**的词（"改革开放新"、"电子计算机化"、"足球比赛"）查 FastText 向量——只有子词模型能回答；
- 类比：`v(中国) - v(北京) + v(巴黎)` 式向量运算。

### 3.3 文本分类

- 文档向量 = 词向量**平均池化**（mean pooling，出现于词表的词取平均）；
- 特征标准化 + 逻辑回归 / 线性 SVM，5 折分层交叉验证，宏平均 F1；
- 类别数**由少到多**：2 类（经济/政务）→ 4 类（+文化/外交）→ 6 类（+科技/体育），"其他"不参与分类。

### 4.3 类比（Word2Vec）

| 类比 | Top-3 结果 | 判定 |
|---|---|---|
| 北京:中国 :: 巴黎:? | 奥地利 / 非洲 / 尼泊尔 | 错（应为法国） |
| 北京:中国 :: 东京:? | **日本** / 秘鲁 / 英格兰 | 对（Top-1） |
| 中国:北京 :: 法国:? | 莫斯科 / 开罗 / **巴黎** | 对（Top-3） |

观察：3 题只中 2 题且名次不理想，与论文（大规模语料上类比准确率可到 60%+）差距明显。原因：3.5M 词的语料太小，"巴黎/法国"这类国家—首都对出现次数不足，向量运算的线性规律尚未充分浮现。**这是语料规模问题，不是方法问题**——这也是把"与论文对照"做实的价值所在。

### 4.4 文本分类（F1 macro，5 折交叉验证）

| 类别数 | n | 向量 | LR | SVM |
|---|---|---|---|---|
| 2（经济/政务） | 1028 | Word2Vec | 0.906 ± 0.011 | 0.901 ± 0.015 |
| 2 | 1028 | FastText | **0.916 ± 0.017** | 0.902 ± 0.018 |
| 4（+文化/外交） | 1503 | Word2Vec | 0.848 ± 0.007 | 0.838 ± 0.014 |
| 4 | 1503 | FastText | **0.857 ± 0.019** | 0.836 ± 0.011 |
| 6（+科技/体育） | 1828 | Word2Vec | 0.837 ± 0.016 | 0.818 ± 0.019 |
| 6 | 1828 | FastText | **0.845 ± 0.008** | 0.816 ± 0.019 |

观察：
1. 第一版 FastText 的 LR 分数在各类数下略高；4 类、6 类的 SVM 得分低于 Word2Vec。子词收益依赖语料和分类器；
2. **LR ≥ SVM 在全部配置**：平均池化后的文档向量已是低维稠密特征，线性可分度较好，SVM 的间隔优化没有带来额外收益；
3. 类别数从 2 → 6，F1 从 0.91 单调降到 0.84：类别越多、类别间边界越细（如"科技"与"经济"在产业新闻上重叠），符合预期；
4. 由于标签是弱标注，绝对 F1 存在噪声上限，但**相同标签下的相对比较是可靠的**。

## 5. 进阶：读论文，对照 Gensim 实现

### 5.1 负采样分布（Mikolov 2013 §2.2）

论文：负采样概率 `P_n(w) ∝ U(w)^{3/4}`（unigram 频率的 3/4 次幂，经验最优）。

gensim 源码对应（`gensim/models/word2vec.py`）：

```python
# __init__ 参数默认值（word2vec.py:244-247）
sample=1e-3, ..., negative=5, ns_exponent=0.75, ...
# prepare_vocab 中构建负采样表（word2vec.py:840-844）
train_words_pow += count**float(self.ns_exponent)   # 3/4 次幂
cumulative  += count**float(self.ns_exponent)
```

`ns_exponent=0.75` 与论文完全一致；实现上用 `cum_table`（累积分布 + 二分/线性查找）代替原版 C 的 1 亿元素 `unigram table`，内存更省。

### 5.2 高频词降采样（Mikolov 2013 §2.3）

论文：以概率 `P(w_i) = 1 − √(t / f(w_i))` 丢弃高频词（t≈1e-5），既加速又提升罕见词向量质量。

gensim 源码对应（`word2vec.py:725-742`）：

```python
threshold_count = sample * retain_total          # sample 默认 1e-3，按论文原意是比例
word_probability = (np.sqrt(v / threshold_count) + 1) * (threshold_count / v)
self.wv.set_vecattr(w, 'sample_int', np.uint32(word_probability * (2**32 - 1)))
```

计数形式的实现是保留概率，化为频率比例时约为 `min(1, √(t/f) + t/f)`，高频时主项才接近论文丢弃概率的补数 `√(t/f)`。Gensim 的 `threshold_count` 以阈值比例乘语料计数，使用整数化的 `sample_int` 减少内层运算。

### 5.3 sigmoid 查表（原版 word2vec 的工程技巧）

负采样的每次更新都要算 σ(x)。gensim 的 Cython 内核（`gensim/models/word2vec_inner.pyx:36-40`）：

```python
DEF EXP_TABLE_SIZE = 1000
cdef REAL_t[EXP_TABLE_SIZE] EXP_TABLE   # 预计算 exp 表
f = EXP_TABLE[<int>((f_dot + MAX_EXP) * (EXP_TABLE_SIZE / MAX_EXP / 2))]
```

用预计算的 1000 项表与整数索引近似 sigmoid，所示路径直接查表。

### 5.4 训练循环：Python 调度 + Cython 内核

`word2vec.py` 的 `_get_next_alpha` 用 `(cur_epoch + epoch_progress) / self.epochs` 计算全程进度，再将学习率从 `alpha` 线性降到 `min_alpha`。`_do_train_job` 把已组成的批和学习率传给 `train_batch_sg` 或 `train_batch_cbow`。窗口内负采样更新在编译的 Cython 内核执行。

### 5.5 FastText 子词哈希（Bojanowski et al. 2017）

论文：词 = 自身向量 + 字符 n-gram 向量之和；n-gram 用哈希映射进固定数量桶控制内存。

gensim 源码对应（`gensim/models/fasttext.py:276-278`）：

```python
negative=5, ns_exponent=0.75, ..., min_n=3, max_n=6,
sorted_vocab=1, bucket=2000000, ...
```

- `bucket=2,000,000`：所有字符 n-gram 哈希到 200 万个桶（论文同样用 2M）；词表再大，n-gram 参数也封顶 = 桶数 × 维度；
- 哈希冲突被容忍（论文实验显示影响很小），这也是 FastText 内存可控的关键设计；
- FastText 沿用词向量训练的总体调度，调用自己的 Cython 批训练内核处理词项和子词向量。`fasttext.py` 的 `ft_ngram_hashes` 通过 `compute_ngrams_bytes` 取得字节串，计算 `ft_hash_bytes(n) % num_buckets`。

## 6. 高级：周边代码与超参数的理解

| 参数 | 位置 | 含义与选择方法 |
|---|---|---|
| `window` | word2vec.py:243 | 上下文窗口。语料小、任务重搭配时取小（本实验 5）；论文默认 5/10 |
| `min_count` | word2vec.py:244 | 低于该频次直接丢弃。5 是常用起点；语料大时可提到 10~20 以去噪提速 |
| `epochs` | `word2vec.py` 的 `_get_next_alpha` | 数据遍历轮数。一次训练调用的学习率按跨轮累计进度衰减。 |
| `shrink_windows` | `word2vec.py` 的构造器说明 | 默认开启。每个目标词的有效窗口在 1 到 `window` 间均匀采样，近邻因此获得更多机会。关闭后使用固定窗口。 |
| `sorted_vocab` | word2vec.py:246 | 词表按频次排序使高频词聚在一起，改善缓存局部性，纯工程优化 |
| `trim_rule` | word2vec.py:246 | 用户自定义词表过滤函数（word2vec.py:648 处调用），可做领域停用词 |
| `batch_words` | word2vec.py:246 | 每次交给 Cython 内核的最大词数，控制峰值内存 |
| `compute_loss` | word2vec.py:246 | 默认 False；True 时每个 batch 汇报损失，调试/画学习曲线用，有少量开销 |
| `ns_exponent` / `sample` | §5.1/§5.2 | 负采样分布指数、降采样阈值，都来自论文 |
| FastText `min_n`/`max_n` | fasttext.py:277 | 字符 n-gram 长度范围。中文建议 1~4（本实验 2~4）；范围过大 → 子词表爆炸，过小 → 失去词形信息 |
| FastText `bucket` | fasttext.py:278 | n-gram 哈希桶数，内存上限开关 |
| FastText 子词哈希 | `fasttext.py` 的 `ft_ngram_hashes` | 子词用确定性的 `ft_hash_bytes` 后对桶数取模。构造器的 `hashfxn` 是词向量初始化相关参数。多线程更新顺序仍可造成结果波动。 |

## 7. 局限与改进方向（诚实评估）

1. **语料规模**：3.5M 词 vs 论文 6B 词，类比任务表现偏弱是规模问题；
2. **标签噪声**："经济"关键词规则过宽（690/1028 篇被标为经济），分类绝对 F1 有噪声上限，改进方向是用 BERT/人工抽查修正子集标签后重评；
3. **未做的对照**：CBOW vs skip-gram、`ns_exponent` 敏感性、`shrink_windows` 开关对比，可作为后续消融；
4. **可做的提升**：先用 `Phrases`（word2phrase）合并"国民经济"类短语再训练；分类改用 TF-IDF 加权平均或 SIF 加权，通常能再提高文档向量质量。
