# L1 可选作业：商业敏感信息识别 —— 研究路径与方案设计

> 对应课件"案例 2：商业敏感信息识别：这是分类问题吗？"（L1 第 167 页）。
> 课程要求：最关切的是**研究路径、过程和思路**，而不是最后的结果；重点回答"如何用大模型辅助进行课题的深入理解、界定研究范围、寻找突破路径"。

## 1. 课题的第一层理解：这不是（单层）分类问题

课件给的第一个关键区分：**识别 ≠ 执行**。

- "本轮报价为 100 万元"这句话是否敏感，取决于**接收者是谁、他有什么授权、组织政策允许什么信息流**。同一个句子，发给项目组内授权成员是正常业务，发给无授权外部人员就是泄漏。
- 所以系统至少分两层：**识别层**（内容属于哪类敏感信息、定位在哪）与**执行层**（结合接收者、授权记录、政策做处置判断）。如果把两层合成一个无来源的"敏感分"，出错时无法定位是哪一层错了——这正是课件"若把这些步骤合成一个无来源的'敏感分'，就难以定位错误"的意思。

由此得到的第一个研究问题：**敏感信息识别系统的正确输出不是"敏感/不敏感"的标签，而是"类别 + 证据位置 + 处置建议"，处置依据必须可复查。**

## 2. 如何用大模型辅助深入理解课题（实际过程记录）

我按以下方式用大模型把课题"拆开"：

1. **概念拆解提问**："商业敏感信息识别与 PII 检测、DLP、数据分类分级是什么关系？"——得到的分层是：个人信息（PII，受个保法约束）是敏感信息的子集；商业敏感信息还包括报价、客户名单、研发资料、合同条款等组织资产；DLP 是落地载体。**这帮助我把"敏感"从直觉词汇变成可枚举的类别体系**；
2. **领域速览**："真实 DLP 系统怎么识别敏感内容？"——检索到行业实践（见 §4），得知生产系统不是纯模型方案，而是规则/指纹/模型/OCR 的组合；
3. **边界提问**："误放行和误阻断各造成什么成本？"——误放行=泄漏事故（不可逆），误阻断=业务停滞+人工复核成本（可逆但有代价），两者**不能用一个准确率指标混评**；
4. **案例构造**：让大模型围绕"报价"句生成接收者×授权×渠道的组合矩阵，作为实验样本草稿（再人工核对）。

用大模型的正确姿势是：**让它提供结构化视角、术语和案例骨架，再用检索核实事实、用课程框架筛选**——大模型给"地图"，事实核查与范围界定仍由人做。

## 3. 研究范围界定

| 维度 | 界定 |
|---|---|
| 对象 | 组织内非结构化文本（邮件、IM 消息、文档摘录）中的商业敏感信息 |
| 敏感类别（识别层输出） | 报价/价格信息、客户名单与联系方式、研发资料、合同条款、财务数据、人事信息（后两类与 PII 有交叉） |
| 情境变量（执行层输入） | 接收者身份与授权、发送渠道（内部/外部）、组织政策 |
| 系统输出 | 类别 + 证据位置（哪个片段）+ 处置建议（放行/复核/阻断） |
| 不在范围内 | 加密流量检测、终端文件管控、法律合规结论（可作为执行层外部输入） |

成功标准（把"输出看起来合理"改写为可检查的要求）：
1. 识别层：对构造测试集，类别 F1 ≥ 基线，且**证据位置正确率**单独报告（定位错误=下游处置依据失效）；
2. 执行层：处置决策必须能回溯到"类别→授权记录→政策条款"的完整依据链；
3. 评价必须同时报告误放行率与误阻断率，并结合基数与用途（见 §5.3）。

## 4. 资料收集与汇编（检索结果）

对 DLP 实践的检索显示（来源见文末）：

- **主流识别技术各有软肋**：关键字/正则最快但误报最高（"身份证号"四个字出现在新闻里也告警）；指纹匹配只防"见过的文件"；文档分类/机器学习覆盖广但冷启动期效果差；OCR 识别截图文字但开销大。**行业共识是"先关键字打底，再叠指纹和模型，把误报当常态治理"**，而不是指望一个模型解决全部问题；
- **一上线就开阻断是经典失败路径**：第一周业务投诉、第二周被迫全局放行、第三周系统弃用——这直接印证课件的"执行层要单独设计、处置要有依据"；
- **DLP 三要素**：数据识别（分类标记）、数据可见性（流动监控）、访问控制（基于角色）；
- **分类分级先行**：没有分类分级，规则只能"地毯式覆盖"，全公司文档都命中——先回答"我们有哪些数据、在哪、哪一种泄露了真的疼"；
- **NLP 语义识别**是补足规则的方向：当敏感信息与预定义模式不匹配时仍能识别（如"本轮报价为 100 万元"没有"机密"字样，规则匹配会漏）。

这些材料把课题锚定到了真实工程约束上：**精度不是唯一目标，误报治理、业务可用性、处置依据同样重要**。

## 5. 技术路径方案（研究设计）

### 5.1 总体管线（识别与执行分离）

```
文本 → [规则引擎] ── 高置信命中 → 标注类别+证据
         │ 未命中
         ↓
     [NER/分类模型] → 类别+证据位置+置信度
         ↓
     [执行层] 类别×接收者×授权×渠道×政策 → 放行 / 人工复核 / 阻断
         ↓
     处置记录（类别、依据、决策、复核结果）→ 审计
```

设计理由：规则引擎处理高模式化信息（身份证号、银行卡号、金额+货币单位），模型处理语义化信息（无关键词的报价、客户名单变体）；执行层**不消费识别层的置信度分数，只消费类别与证据**，处置逻辑全部来自授权记录与政策，可回溯。

### 5.2 数据集构造（无现成标注数据时的路径）

1. **构造语料**：从公开商业文本（公告、新闻、示例邮件）中抽取句子，再人工改写注入敏感信息（报价、客户名、研发描述），并保留一批**不注入的对照句**；
2. **授权矩阵**：定义 4 类接收者（项目组内/组外员工/合作方/外部），每类×每敏感类别的允许/禁止矩阵，作为执行层的"政策"输入；
3. **标签**：识别层标签=类别+起止位置；执行层标签=处置决策；
4. 诚实说明：构造数据的分布不等于真实流量分布，因此**结论只说明"在构造分布上的相对比较"**，上线前必须在真实流量上做影子评估。

### 5.3 评价协议（误放行与误阻断分开）

- **误放行**（该阻断的放行了）：直接按泄漏事故计，权重最高，且要求逐例复盘；
- **误阻断**（该放行的拦了）：按人工复核成本计（分钟数×人力成本），与误放行**分列报告**，不合并成一个准确率；
- **基线与用途**：报告两类错误在总流量中的基数占比；"财务数据"的误放行与"报价"的误阻断权重不同——**评价矩阵由业务方给定，不由模型方自定**；
- 每例处置保留依据链（类别→证据→授权→政策），供审计抽查。

### 5.4 能区分解释的小实验（课程要求的对照设计）

**关键条件变化样本对**（同一内容、不同情境）：

> 样本 A："本轮报价为 100 万元。" 发送给项目组内已授权成员 → 预期：放行。
> 样本 B：同句发送给无授权的外部联系人 → 预期：阻断/复核。

判断方法：若系统对 A/B 给出不同处置且依据正确，说明执行层**真正消费了情境变量**；若两者处置相同，说明系统仍在做"内容=敏感→一律阻断"的单层判断，定位到执行层缺失。

**答案应保持不变的控制样本对**（情境不同、结论应相同）：

> 样本 C："下周例会改到周三下午。" 发给组内成员 → 放行。
> 样本 D：同句发给外部联系人 → 仍应放行（无敏感内容）。

判断方法：若 D 被阻断，说明识别层误报污染了执行层（"发外部"被当成了敏感信号）；若 C/D 都放行，说明识别层没有把"渠道"误当内容特征。

这两组样本分别检验**执行层是否在场**与**识别层是否误报**，是"一个能区分解释的实验"的最小形式。真实运行结果见 §5.5。

## 5.5 最小演示的运行结果（2026-11-24 复验）

用 `run_mini_demo.py` 实现了 §5.1 管线的最小版：识别层 = 正则 + 关键词规则（6 类别，输出类别 + 证据位置），执行层 = 4 类接收者 × 6 类别的授权矩阵（放行/复核/阻断 + 完整依据链）。8 个样本的运行结果：

| 样本 | 内容 | 接收者 | 处置 | 预期 |
|---|---|---|---|---|
| A | 本轮报价为 100 万元。 | 项目组内 | 放行 | 放行 ✓ |
| B | 同上 | 外部 | **阻断** | 阻断 ✓ |
| C | 下周例会改到周三下午。 | 项目组内 | 放行 | 放行 ✓ |
| D | 同上 | 外部 | 放行 | 放行 ✓ |
| E | 新闻里报道某公司工资薪酬情况，与我们无关。 | 外部 | 阻断（**误报**） | 应放行 |
| F | 客户联系手机 138…、邮箱 … | 组外员工 | 复核 | 复核 ✓ |
| G | 本季度营收 2.3 亿元，员工绩效表见附件。 | 组外员工 | 阻断 | 阻断 ✓ |
| H | 报价单 45 万元已按合同条款发送。 | 合作方 | 放行（经引用排除） | 放行 ✓ |

六个结构性检查全部通过。以教学样本期望决策为准，应阻断或复核的 3 条中误放行 0 条，应放行的 5 条中误阻断或复核 1 条。以下说明具体案例。

1. 关键对 A/B 处置不同且依据正确 → **执行层真正消费了情境变量**（内容相同、接收者不同、处置不同）；
2. 控制对 C/D 均放行 → 识别层没有把"发外部"误当内容特征；
3. 样本 E 的“工资／薪酬”触发关键词误报，说明规则需结合来源与组织归属；
4. 样本 H 第一次运行被误判复核（"合同条款"关键词命中"按合同条款发送"），加**引用模式排除**（"按/依照…合同"为引用而非发送合同文本）后正确放行——这是"误报治理"规则迭代的最小实例。

**诚实边界**：规则集与授权矩阵为教学构造（8 样本、6 类别、4 接收者），不是可上线的 DLP 系统；结果只证明"识别与执行分离 + 依据链"的设计逻辑可运行，不代表生产表现。复现：`python task8_sensitive/run_mini_demo.py`（纯标准库，零依赖）。

## 6. 可能的突破路径（按性价比排序）

1. **先做识别层评测，不碰执行层**：识别层的类别 F1 + 证据位置正确率是可控的研究问题，数据可构造、指标可计算；
2. **把"误报治理"本身作为研究对象**：按规则命中次数排序优化高频误报规则、开业务申诉入口、每周抽样复核——课件与行业实践都表明这是真实价值点，且不依赖大规模算力；
3. **语义识别补规则**：用 NER/分类模型补关键字漏检（无关键词的报价句），这也是最能与本课程其他任务（BERT 微调）衔接的路径；
4. 远期：影子模式上线，在真实流量上积累误放行/误阻断基线后再谈策略自动化。

## 7. 结论（研究路径的凝练）

这个课题的"可研究内核"是：**敏感信息的处置是"内容 × 情境 → 有依据的决策"，而不是"内容 → 敏感分"**。因此可行的研究路径是：把识别（可构造数据、可计算指标）与执行（依赖授权与政策、必须可回溯）分开设计，用"关键条件变化样本对 + 控制样本对"检验两层各自是否在场，用误放行/误阻断分列报告评价，而不是追求一个漂亮的单点准确率。
